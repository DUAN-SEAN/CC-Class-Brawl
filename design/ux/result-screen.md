## Purpose & Player Need

结算界面的核心目标是快速、清晰地展示对局结果，并提供"再来一局"的最小阻力入口。

**玩家到达时想做的事**：知道谁赢了，确认结果，然后立刻再来一局（大部分情况）。

**如果没有这个界面会怎样**：对局结束直接切回角色选择，玩家不知道比分，失去比赛叙事感。但这个界面必须极快——游戏状态管理要求 Results → CharacterSelect 过渡 < 0.5s。

**核心设计约束**：
- 从看到结果到点击"再来一局"不超过 3 秒
- 结果显示清晰，但不需要详细统计数据（这是派对游戏，不是竞技分析）
- "再来一局"是主操作，退出是次要操作

**情感目标**：
- 胜利：庆祝、爽快、派对高潮——"VICTORY!" + 胜者职业色爆发（美术圣经 §2.6）
- 失败：轻松鼓励、"我不服，再来！"——不是被压制的暗淡，而是"下次能赢"的期待（美术圣经 §2.7）

---

## Player Context on Arrival

**何时遇到**：对局 KO 后，1 秒冻结帧（BattleEnd）结束。

**从哪里来**：战斗界面。玩家刚刚经历了 3-5 分钟的激烈战斗，胜负已分。

**情绪状态**：
- 胜者：兴奋、成就感、"我打出来了！"
- 败者：不服、分析"我应该在哪里做选择"、期待"再来一局"

**到达方式**：被游戏引导至此——战斗自动触发状态转换。

---

## Navigation Position

结算界面是单局战斗的终点，下一局的起点。

**层级定位**：`[根] → 主菜单 → 角色选择 → [战斗序列] → 结算界面`

从结算界面出发，玩家可以进入：
- 角色选择（再来一局）— 最常用路径，< 0.5s 过渡
- 主菜单（退出）— 次要路径，< 2s 过渡

结算界面在 GameScene 中实现，与战斗结果共享同一场景（背景保持战场）。

## Entry & Exit Points

### 入口

| 入口来源 | 触发方式 | 玩家携带的上下文 |
|---------|---------|----------------|
| 战斗结束 (BattleEnd) | KO 发生，1 秒冻结帧结束 | 胜者索引、最终比分 |

### 出口

| 目的地 | 触发方式 | 备注 |
|-------|---------|------|
| 角色选择（再来一局） | 任意玩家按 A / Enter | 过渡 < 0.5s，场景不重新加载，角色选择保持 |
| 主菜单（退出） | 选择"退出到菜单"并确认 | 过渡 < 2s，GameScene 卸载 |

## Layout Specification

### Information Hierarchy

1. **"VICTORY!" 或 "DEFEAT"** — 最高优先级，一秒内判读结果
2. **最终比分** — 次要，确认整场比赛结果
3. **"再来一局"按钮** — 核心交互，最显眼
4. **"退出到菜单"选项** — 最低，角落小字

### Layout Zones

- **中央结果区** — "VICTORY!" / "DEFEAT" + 胜者职业色光效
- **比分显示** — 中央下方，如 "2 - 1"
- **操作提示** — 屏幕底部中央，"按 A 再来一局"
- **背景** — 战场定格，暗色遮罩半透明叠加

### Component Inventory

| 区域 | 组件 | 类型 | 内容 | 交互 | 备注 |
|------|------|------|------|------|------|
| 中央结果区 | 结果文字 | 文字 | "VICTORY!" / "DEFEAT" | 显示 | 大字号，职业色（胜利）或暗色（失败） |
| 比分显示 | 比分数字 | 文字 | "2 - 1" | 显示 | 中等字号，白色 |
| 操作提示 | 再来提示 | 文字 + 按钮 | "按 A 再来一局" | 可交互 | 主操作焦点 |
| 底部角落 | 退出选项 | 文字 | "退出到菜单：按 B" | 可交互 | 次要操作 |

### ASCII Wireframe

```
┌─────────────────────────────────────────────────────────┐
│                   [战场定格背景，半透明暗遮罩]           │
│                                                         │
│                  ████████████                           │  ← VICTORY! (胜者职业色)
│                  VICTORY!                                │
│                                                         │
│                    2 - 1                                │  ← 最终比分
│                                                         │
│                                                         │
│                [再来一局]   (按 A)                       │  ← 主操作
│                                                         │
│       退出到菜单 (按 B)                                 │  ← 次要操作
└─────────────────────────────────────────────────────────┘
```

**P1 胜利 vs P2 胜利**：中央结果区文字相同（"VICTORY!" 或 "DEFEAT"），但玩家需要知道"谁赢了"。解决方案：结果文字下方显示 "PLAYER 1 WINS" 或 "PLAYER 2 WINS" 小字。

## States & Variants

| 状态/变体 | 触发条件 | 界面变化 |
|----------|---------|---------|
| **P1 胜利** | P1 KO P2 | 显示 "VICTORY!" + P1 职业色光效 + "PLAYER 1 WINS" |
| **P2 胜利** | P2 KO P1 | 显示 "VICTORY!" + P2 职业色光效 + "PLAYER 2 WINS" |
| **进入动画** | 从 BattleEnd 转换 | 淡入 + "VICTORY!" 弹出动画（0.3s） |
| **平局（未来）** | 同时 KO（MVP 不实现） | 显示 "DRAW!" + 中性色 |

MVP 不支持平局——击退系统确保总有一方先出局。 |

## Interaction Map

**输入方式**：任意玩家操作（P1 或 P2 都可以触发"再来一局"）。

| 组件 | 动作 | 手柄输入 | 键盘输入 | 即时反馈 | 结果 |
|------|------|---------|----------|---------|------|
| 再来一局 | 确认 | 任意手柄 A | Enter / 空格 | 按钮缩放 + 音效 | 进入角色选择 |
| 退出到菜单 | 退出 | 任意手柄 B | Escape | 无（或确认弹窗） | 进入主菜单 |

**特殊规则**：P1 和 P2 都可以触发"再来一局"，因为这是派对游戏，不需要"轮流决定"。任一人按键即可。

---

## Events Fired

| 玩家操作 | 触发事件 | 载荷/数据 | 备注 |
|---------|---------|----------|------|
| 选择"再来一局" | `OnRematchRequested` | 无 | 触发 GameState → CharacterSelect |
| 选择"退出到菜单" | `OnMainMenuRequested` | 无 | 触发 GameState → MainMenu |

遥测：记录比赛结果、耗时、局数（由对局管理系统提供，结算界面仅负责传递）。

## Transitions & Animations

### 屏幕进入过渡（BattleEnd → Results）
- **效果**：淡入 + "VICTORY!" 文字弹出
- **时长**：0.3 秒
- **背景**：战场定格 + 半透明暗色遮罩渐显

### 胜利动画
- **效果**（美术圣经 §2.6）：胜者职业色从中心向四周快速扩散（约 1.5s），然后暗色回弹
- **粒子**：职业色几何碎片向上弹射（战士=矩形、法师=三角、盗贼=菱形）

### 失败动画
- **效果**（美术圣经 §2.7）：失败方职业色柔和渲染背景（15%），微弱脉动（2秒周期+2%/周期）
- **无**：碎裂、暗淡、暗角

### 屏幕退出过渡（Results → CharacterSelect）
- **效果**：快速淡出
- **时长**：< 0.5 秒（游戏状态管理约束）

### 屏幕退出过渡（Results → MainMenu）
- **效果**：淡出到黑屏
- **时长**：< 2 秒

## Localization Considerations

| 文本元素 | 最大中文字符数 | 预计英文字符数 | 扩展风险 | 备注 |
|---------|--------------|--------------|---------|------|
| "VICTORY!" | 2 | 7 | 低 | 大字号，固定宽度 |
| "DEFEAT" | 2 | 5 | 低 | 大字号，固定宽度 |
| "PLAYER X WINS" | ~8 | ~14 | 低 | 小字号 |
| 比分 "X - Y" | 5 | 5 | 无 | 数字不扩展 |
| "按 A 再来一局" | ~8 | ~20 | 中 | 底部提示区支持换行 |
| "退出到菜单" | ~6 | ~15 | 低 | 小字号 |

**布局弹性要求**：
- 中央结果文字固定宽度，居中显示
- 底部操作提示区自适应宽度

## Acceptance Criteria

- [ ] KO 后 1 秒内显示结算界面
- [ ] "VICTORY!" 或 "DEFEAT" 文字清晰，配合胜者职业色光效
- [ ] 最终比分显示正确（如 "2 - 1"）
- [ ] 按 A/Enter 后 0.5 秒内进入角色选择界面
- [ ] P1/P2 都可以触发"再来一局"
- [ ] 背景保持战场定格 + 半透明暗遮罩

## Open Questions

1. **退出确认**：本规格未包含退出确认弹窗（与主菜单不同）。是否需要二次确认防止误操作？建议不需要——"再来一局"是主操作，退出需要按 B（退出键）且进入菜单需要 <2s 过渡，误操作影响有限。

2. **战场定格时长**：当前设计假设战场保持定格直到进入下一状态。是否有时间限制？（如 30 秒无操作自动退出？）

3. **详细统计数据**：本规格仅显示比分和胜负，未包含技能使用数、最高伤害等详细统计。这是派对游戏的简洁设计，但后续是否需要"查看详情"选项？
