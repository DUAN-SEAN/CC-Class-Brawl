## Purpose & Player Need

角色选择界面的核心目标是让玩家快速理解每个职业的差异并做出选择。

**玩家到达时想做的事**：看到所有可用的职业，理解每个职业的独特玩法，选择一个自己喜欢的，和朋友一起进入战斗。

**如果没有这个界面会怎样**：游戏随机分配职业——这破坏了"我就是这个角色"的幻想（class-system GDD），玩家失去了选择自己风格的机会。

**核心设计约束**：
- 从看到第一个职业选项到完成选择，不应超过 10 秒
- 每个职业的差异必须在 3 秒内可感知（形状、颜色、一句话描述）
- 符合游戏支柱"秒学秒玩"——不需要阅读长篇文档就能理解

**情感目标**：轻松、社交、期待——像朋友围坐在茶几旁讨论"我玩战士，你玩什么？"（美术圣经 §2.1）。暖色调背景（#222240）支持这种氛围。

**与主菜单的区别**：主菜单只有一行"开始对战"；角色选择是第一个让玩家表达个性的地方。但同样不拖沓——这不是"角色百科"，是"角色选择"。

## Player Context on Arrival

**何时遇到**：从主菜单选择"开始对战"后，游戏场景从 MenuScene 切换到 GameScene，游戏状态进入 CharacterSelect。

**从哪里来**：主菜单。玩家刚刚按了"开始对战"，期待看到角色选项。

**情绪状态**：期待 + 选择兴奋——"这次我玩什么？"这是整局游戏中玩家第一次表达个性的时刻。同时有社交期待——和朋友一起看选项，可能交换建议。

**到达方式**：被主菜单引导至此——不是主动寻找。

**身边环境**：本地多人场景——两个手柄已连接，两个朋友都在看屏幕。界面需要支持两个人同时选择，但不能互相干扰。

---

## Navigation Position

角色选择是游戏流程中的第二个节点，位于主菜单之后。

**层级定位**：`[根] → 主菜单 → 角色选择`

从角色选择出发，玩家可以进入：
- 对局加载（MatchLoading）—— 所有玩家确认角色选择后
- （MVP 无返回路径——角色选择后只能前进，不能回主菜单。返回菜单仅在结算界面提供）

角色选择在 GameScene 中实现，与倒计时、战斗、结果界面共享同一个场景。

## Entry & Exit Points

### 入口

| 入口来源 | 触发方式 | 玩家携带的上下文 |
|---------|---------|----------------|
| 主菜单 | 选择"开始对战"并确认 | 无 — 新的对局会话 |

### 出口

| 目的地 | 触发方式 | 备注 |
|-------|---------|------|
| 对局加载 (MatchLoading) | 所有玩家确认角色选择 | 触发 GameState 从 CharacterSelect → MatchLoading，初始化时间 < 1s |

### 特殊状态

| 状态 | 条件 | 处理 |
|------|------|------|
| 等待对方选择 | P1 已确认，P2 未确认 | P1 界面显示"等待 P2 选择"，不锁定操作（P1 可更改选择） |
| 同职业选择 | 两人选择相同职业 | 允许（"镜像战"），视觉上通过 P1/P2 标识色区分 |

## Layout Specification

### Information Hierarchy

1. **P1/P2 各自的选择区域** — 最高优先级。每个人需要知道自己选了什么，并能更改。
2. **职业选项列表** — 次要。需要能看到所有可用职业（战士、法师、盗贼）。
3. **确认状态指示** — 次要。需要知道双方是否已确认，以及是否"等待对方"。

### Layout Zones

- **P1 选择区（屏幕左半）** — P1 的职业选择、预览、确认控制
- **P2 选择区（屏幕右半）** — P2 的职业选择、预览、确认控制
- **中央分隔线** — 视觉分隔，避免双方干扰
- **顶部状态栏** — 显示"等待 P1/P2 选择"等状态信息

## States & Variants

| 状态/变体 | 触发条件 | 界面变化 |
|----------|---------|---------|
| **默认状态** | 界面首次加载 | P1/P2 选择区都显示"未选"，职业卡片可用 |
| **P1 已选择** | P1 选择职业但未确认 | P1 预览区显示选中职业，P1 确认按钮显示"确定" |
| **P1 已确认** | P1 按确认按钮 | P1 确认按钮变为"更改"，P1 职业卡片锁定（但仍可导航） |
| **双方已确认** | P1 和 P2 都确认 | 顶部状态栏显示"准备开始"，短暂延迟后进入 MatchLoading |
| **等待对方** | 一方确认，另一方未确认 | 已确认方的预览区显示"等待对方选择..."提示 |
| **同职业选择** | 双方选择相同职业 | 正常处理（允许镜像战），预览区显示 P1/P2 标识色区分 |

## Interaction Map

**输入方式**：手柄（主输入）+ 键盘（备用）。

| 组件 | 动作 | 手柄输入 | 键盘输入 | 即时反馈 | 结果 |
|------|------|---------|----------|---------|------|
| P1 职业卡片 | 导航 | P1 方向键 ←/→ | A/D 键 | 卡片高亮移动 + 音效 | 切换焦点到目标职业 |
| P1 确认按钮 | 确认选择 | P1 A | 空格键 | 按钮缩放 + 音效 | P1 进入"已确认"状态 |
| P1 更改按钮 | 更改选择 | P1 A | 空格键 | 按钮缩放 + 音效 | P1 回到"已选择"状态，可更改职业 |
| P2 职业卡片 | 导航 | P2 方向键 ←/→ | ←/→ 方向键 | 卡片高亮移动 + 音效 | 切换焦点到目标职业 |
| P2 确认按钮 | 确认选择 | P2 A | Enter 键 | 按钮缩放 + 音效 | P2 进入"已确认"状态 |
| P2 更改按钮 | 更改选择 | P2 A | Enter 键 | 按钮缩放 + 音效 | P2 回到"已选择"状态，可更改职业 |

**焦点起始位置**：P1 和 P2 的焦点各自独立，P1 聚焦在第一个职业卡片，P2 聚焦在第一个职业卡片。

**焦点隔离**：P1 无法导航到 P2 的区域，反之亦然。这是防止双人冲突的关键设计。

## Events Fired

| 玩家操作 | 触发事件 | 载荷/数据 | 备注 |
|---------|---------|----------|------|
| P1 选择职业 | `OnCharacterSelected` | `player_id: 1, class_id: string` | 更新 P1 选择状态 |
| P1 确认选择 | `OnCharacterConfirmed` | `player_id: 1, class_id: string` | P1 进入确认状态，检查是否双方都确认 |
| P2 选择职业 | `OnCharacterSelected` | `player_id: 2, class_id: string` | 更新 P2 选择状态 |
| P2 确认选择 | `OnCharacterConfirmed` | `player_id: 2, class_id: string` | P2 进入确认状态，检查是否双方都确认 |
| 双方都确认 | `OnAllPlayersReady` | `[{player_id: 1, class: ...}, {player_id: 2, class: ...}]` | 触发 GameState → MatchLoading |

## Transitions & Animations

### 屏幕进入过渡（主菜单 → 角色选择）
- **效果**：淡入 + 区域渐显
- **时长**：0.3-0.5 秒
- **顺序**：背景 → P1/P2 区域 → 职业卡片

### 屏幕退出过渡（角色选择 → MatchLoading）
- **效果**：淡出到黑屏
- **时长**：0.3 秒
- **注意**：符合 GDD 约束的 <1s 初始化时间

### 状态变化动画
- **职业卡片高亮**：缩放 + 职业色边框发光
- **确认按钮**：确认时按钮放大 + 音效，变为"更改"时缩小
- **预览区**：选择职业后，职业预览从卡片区"飞"到预览区（0.2s）

### 等待对方动画
- 当一方已确认时，该方的预览区显示脉动的"等待..."文字（2秒周期）

### 减少动作模式
- 可通过设置选项禁用所有过渡动画

## Localization Considerations

| 文本元素 | 最大中文字符数 | 预计英文字符数 | 扩展风险 | 备注 |
|---------|--------------|--------------|---------|------|
| 职业名称 | 2-4 | ~8-12 | 中 | "Warrior"/"Mage"/"Rogue" |
| 职业描述 | ~10 | ~20-30 | **高** | 预览区需支持换行 |
| "确定" | 2 | ~6 | 低 | "Confirm" |
| "更改" | 2 | ~6 | 低 | "Change" |
| "等待对方选择" | 6 | ~15 | 中 | "Waiting for player..." |

**布局弹性要求**：
- 职业卡片固定宽度，内容居中
- 预览区描述文本自动换行，预览区高度固定
- 左右分栏等宽，小尺寸屏幕可能需要压缩预览区

## Acceptance Criteria

- [ ] 角色选择界面在场景切换后 0.5 秒内完全显示
- [ ] P1 和 P2 可以独立操作，互不干扰
- [ ] 双方都确认选择后，1 秒内进入 MatchLoading 状态
- [ ] 允许双方选择相同职业（镜像战）
- [ ] 已确认的玩家可以更改选择（"更改"按钮有效）
- [ ] P1/P2 焦点完全隔离，无法导航到对方的区域
- [ ] 职业卡片清晰显示职业名称、颜色和一句话描述

## Open Questions

1. **职业描述的具体内容** — 本规格假设每个职业有一句话描述，但 class-system GDD 中的 ClassDescription 字段的具体内容待定。需要文案团队提供。

2. **职业预览的具体形式** — 本规格假设预览区显示职业的大图标，但不确定是角色剪影、3D 模型还是美术插画。这是美术团队的决策。

3. **3-4 人扩展的布局** — MVP 仅支持 2 人，未来扩展到 3-4 人时需要重新设计布局（可能改为十字分栏）。本规格未考虑扩展路径。

4. **MVP 职业数量** — 本规格列出战士、法师、盗贼三个职业，但 class-system GDD 的 MVP 职业定义需要确认。
